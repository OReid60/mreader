# Release notes and publication

- Update `docs/PATCH-NOTES.md` for every release, newest version first, including behavior changes and validation limits.
- Keep the README and download guide linked to the current release and patch-notes page.
- Before deleting old GitHub releases, archive their notes in the patch-notes page. Keep the current release and one previous stable release for rollback unless the user requests otherwise. Git tags and source history are retained.
- Do not publish credentials, installed extension state, manga data or third-party extension repository URLs. Historical notes must not reintroduce removed repository links.
